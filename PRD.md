# Product Requirements Document (PRD): sec-lab

> A deliberately vulnerable practice app with SAST/DAST pipelines and CTF-style challenges. Local use only.

Open work is tracked in [GitHub Issues](https://github.com/bamr87/sec-lab/issues) and as `status: planned` entries in [features/features.yml](features/features.yml).

## 1. Overview

Break things on purpose: an intentionally vulnerable web app, the scanners that find the bugs (Semgrep, Bandit, ZAP), and write-ups for each fix.

| Version | Date | Notes |
| --- | --- | --- |
| 0.1 | 2026-10-28 | Initial requirements and phased roadmap (repo foundation). |

## 2. Goals

- Intentionally vulnerable app covering OWASP Top 10 classes, run only on localhost
- SAST (Semgrep/Bandit) and DAST (OWASP ZAP) pipelines with reports
- CTF challenge set with flags and fix write-ups

Non-goals (near term): production hosting, paid services, anything outside the roadmap below without a PRD change.

## 3. Users

- The maintainer, learning application security (owasp top 10), static and dynamic analysis tooling by building.
- Fleet agents (hub evolution loop, backlog fan-out, `evolve` lane) that grow the repo one reviewed PR at a time.
- Fleet tie-in: Security patterns learned here feed fleet hardening (zer0-id, edge-gateway, hub security kit).

## 4. Requirements

Phases are the build order: an agent picks the earliest unserved requirement first.

### 4.1 Phase 1 — Foundation

- FR1: Minimal app binds to 127.0.0.1 only and serves a health route, with tests
- FR2: Safety guard: refuses to start on a non-loopback bind without an explicit flag

### 4.2 Phase 2 — Core

- FR3: First challenge set: SQL injection and XSS with flags
- FR4: SAST workflow (Semgrep + Bandit) publishing SARIF

### 4.3 Phase 3 — Fleet integration

- FR5: DAST baseline scan with OWASP ZAP in CI against a container
- FR6: Fix write-ups linked per challenge

### 4.4 Non-functional

- NFR1: CI (`.github/workflows/ci.yml`, the fleet standard gate) passes on every PR.
- NFR2: No secrets or credentials are committed; configuration comes from environment variables.
- NFR3: Autonomous lanes are off by default, open pull requests only, and never merge.
